# eBPF 内核透明代理 ⚡ (Linux Only)

`clash-rs` 原生支持基于 Linux eBPF（TC Ingress/Egress 与 Cgroup BPF Hook）的高性能内核态透明代理引擎。

相比于传统的 iptables / nftables TProxy 方案，eBPF 具备**近线速转发**、**零数据包拷贝**以及**内核态直连快路径自动卸载 (Direct Fast-Path Offload)** 优势，特别适合软路由、旁路网关与高并发边缘网关场景。

::: warning 环境前置要求
- 仅支持 Linux 操作系统。
- Linux 内核版本建议 `>= 5.15`。
- 必须具备 `CAP_NET_ADMIN` / `CAP_BPF` 或以 `root` 权限运行。
- 编译时需包含 `ebpf` 特性标志。
:::

---

## 核心配置速查

```yaml
ebpf:
  enable: true
  lan-interface: ["auto"]
  wan-interface: "auto"
  tproxy-port: 12345
  auto-direct-offload: true

  lan:
    bypass-src-ports: [22, 67, 68, 5353]
    # proxy-src-macs: ["00:11:22:33:44:55"] # 可选：局域网客户端源 MAC 白名单过滤

  target:
    bypass-dst-ports: [123, 500, 4500]

  host:
    proxy-local: false
```

## 顶层与网络接口字段规格表

| 配置字段 | 类型 | 是否必填 | 默认值 | 详细说明与取值 |
| :--- | :--- | :--- | :--- | :--- |
| **`enable`** | 布尔值 | **必填** (若使用 eBPF) | `false` | 是否开启 eBPF 内核级透明代理子系统。 |
| **`lan-interface`** | 字符串列表 | 可选 | `["auto"]` | 局域网接入流量拦截网卡列表（TC Ingress Hook）。填 `["auto"]` 自动发现活跃网桥（如 `br-lan`）与物理网卡；也可显式指定如 `["eth0", "br-lan"]`。 |
| **`wan-interface`** | 字符串 | 可选 | `"auto"` | 广域网外网出口网卡（TC Egress Hook，用于拦截宿主机本机出站流量）。填 `"auto"` 自动跟随系统默认物理网关。 |
| **`tproxy-port`** | 整数 (1-65535) | 可选 | `12345` | 配合 eBPF 接收重定向流量的内部透明代理端口。 |
| **`auto-direct-offload`**| 布尔值 | 可选 | `true` | **内核态直连快路径卸载**。一旦路由引擎裁决某 IP 走直连，自动将其写入内核 eBPF LRU Map，后续流量完全在内核层线速直放，不再进入用户态，极大降低 CPU 占用。 |
| **`routing-mark`** | 整数 (u32) | 可选 | 无 | eBPF 子系统出站流量的路由标记。 |
| **`bypass-dscp`** | 整数列表 (u8) | 可选 | `[]` | 根据 DSCP 标记在内核层秒级放行直连（别名: `bypass-dscps`）。常用于为 BT/P2P 下载客户端流量放行。 |
| **`bypass-fwmark`** | 整数列表 (u32) | 可选 | `[]` | 根据数据包已有的 fwmark 防火墙标记直接放行（支持十进制如 `512` 或十六进制如 `0x200`）。 |

## 细粒度策略模块规格说明

### 1. 局域网接入策略 (`lan:`)

针对局域网接入客户端设备的控制：

| 字段 | 类型 | 是否必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **`bypass-src-ports`** | 整数列表 (u16) | 可选 | `[22, 67, 68, 5353]` | 绕过代理的源端口（默认放行路由器 SSH 22、DHCP 67/68、mDNS 5353）。 |
| **`proxy-src-ports`** | 整数列表 (u16) | 可选 | `[]` | 仅代理这些源端口的流量（若非空，其余源端口一律直连）。 |
| **`bypass-src-ips`** | 字符串列表 | 可选 | `[]` | 直连绕过代理的局域网客户端 IP/CIDR（别名: `bypass-clients`，支持 `rule-set:name`）。 |
| **`proxy-src-ips`** | 字符串列表 | 可选 | `[]` | 仅代理这些客户端（别名: `proxy-clients`，若声明则未列出的局域网设备全部直连）。 |
| **`proxy-src-macs`** | 字符串列表 | 可选 | `[]` | **局域网设备源 MAC 白名单过滤**（别名: `proxy-macs`, `src-macs`）。仅代理指定 MAC 地址的局域网客户端流量。 |

::: tip 💡 局域网源 MAC 过滤详解 (`proxy-src-macs`)
- **工作机制**：eBPF TC Ingress 挂载点直接在数据链路层（L2 以太网帧）提取数据包的源 MAC 地址并查询内核 Hash Map。一旦配置了该列表，**仅有源 MAC 命中白名单的局域网设备**才会进入透明代理调度；非白名单设备以及无法提取二层 MAC 地址的报文（如纯 L3 隧道或非以太网网卡）将在内核中直接快速放行（`TC_ACT_OK` 直连），绝不拦截且杜绝未代理客户端的数据泄漏。
- **地址格式支持**：兼容标准冒号分隔（如 `"00:11:22:33:44:55"`）与连字符分隔（如 `"00-11-22-33-44-55"`），大小写均可，启动时将自动校验格式合法性。
- **容量上限**：最大支持配置 **1024** 个 MAC 地址。
:::

### 2. 目标目的地策略 (`target:`)

对访问的目标服务与 IP 实施控制（对局域网与宿主机流量均生效）：

| 字段 | 类型 | 是否必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **`bypass-dst-ports`** | 整数列表 (u16) | 可选 | `[]` | 直连绕过的目标端口（如 NTP 时间同步 123、IPSec 500/4500 等）。 |
| **`proxy-dst-ports`** | 整数列表 (u16) | 可选 | `[]` | 仅代理的目标端口（如声明 `[80, 443]`，则其他端口流量完全不走代理）。 |
| **`bypass-dst-ips`** | 字符串列表 | 可选 | 包含基础保留段 | 直连绕过的目标网段。默认已放行环回与链路本地地址（`127.0.0.0/8`、`169.254.0.0/16`、`224.0.0.0/4`、`::1/128`、`fe80::/10`、`ff00::/8`）。支持自定义局域网段与 `rule-set:name` 规则集。 |
| **`proxy-dst-ips`** | 字符串列表 | 可选 | `[]` | 目标 IP 白名单（若声明，仅访问匹配这些 IP 的流量会被代理）。 |

---

### 3. 宿主机本机流量与进程策略 (`host:`)

针对运行 `clash-rs` 的软路由或 Linux 宿主机自身发出的网络请求：

| 字段 | 类型 | 是否必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **`proxy-local`** | 布尔值 | 可选 | `false` | 是否代理软路由宿主机本机发出的网络请求。作为旁路网关时通常保持 `false`；桌面 Linux 或主路由需本机代理时设为 `true`。 |
| **`proxy-processes`** | 字符串列表 | 可选 | `[]` | 进程白名单（别名: `proxy-process`）。若非空，宿主机上**仅有**匹配这些进程名（comm）的流量才会被代理。 |
| **`bypass-processes`** | 字符串列表 | 可选 | `[]` | 进程黑名单（别名: `bypass-process`）。匹配这些进程名的流量绝对不走代理（如 `["sshd", "rsync"]`）。 |
